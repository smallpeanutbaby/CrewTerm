# CrewTerm Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Neither execution skill is installed in this session; manually follow their per-task implementation, review and verification workflow. The applicable writing-plans skill authorizes delegation of independent modules.

**Goal:** Build the user-approved C# terminal workspace in `D:\代码\CrewTerm` and deliver a tested Windows executable.

**Architecture:** Terminal.Gui client talks to a current-user named-pipe daemon owning ConPTY sessions. Workspace and automation libraries expose independently testable services. A shared core stores project/profile configuration without depending on UI or native handles.

**Tech Stack:** C#, .NET 10, Terminal.Gui 2 stable, Windows ConPTY, Git CLI, xUnit.

## Global Constraints

- Product: CrewTerm; command: `crewterm`; Chinese description: 多 Agent 协作终端.
- Primary verified platform: native Windows x64, .NET 10, Windows Terminal/PowerShell.
- No production behavior before an observed failing test. Framework project metadata/docs have no behavior and are bootstrapped first.
- Preserve user edits. Use arguments rather than interpolated shell strings for Git and internal commands.
- Keep each module in its assigned source/test directories. Root integration owner edits App, Core, shared config and docs.
- Each module records RED/GREEN commands in `docs/verification-<module>.md`.

## Task 4: Agent profiles, tasks and pipelines

Files: `src/CrewTerm.Automation/{AgentProfile,AgentCatalog,TaskRunner,TaskHistory,PipelineRunner,AgentStateTracker}.cs`; corresponding tests.

Produces profiles/discovery and a bounded cancellable process runner. `CommandTask(string Name,string Command,string WorkingDirectory)`, `TaskRunner.RunAsync(CommandTask,Action<string>?,CancellationToken)` returns a result with ID/name/command/cwd/start/end/exit code/output/cancelled. Pipelines take an ordered list and stop on failure. State distinguishes running/needs-input/exited/unknown, without equating process activity with successful work.

- [ ] RED real command example:
```csharp
var result = await new TaskRunner().RunAsync(new("check", "echo hello & exit /b 7", root), null, default);
Assert.Equal(7, result.ExitCode);
Assert.Contains("hello", result.Output);
```
- [ ] RED pipeline: a failing first step followed by a marker-file-writing second step must leave no marker.
- [ ] Implement captured output, cancellation/tree kill, bounded concurrency, history persistence and profile discovery (including Windows `.cmd` shims).
- [ ] GREEN: `dotnet test tests/CrewTerm.Automation.Tests`; review and commit exact files.

## Task 5: Daemon and CLI integration

Files: `src/CrewTerm.App/Server/{DaemonHost,DaemonClient,Protocol}.cs`, `Program.cs`; `tests/CrewTerm.App.Tests/DaemonTests.cs`.

Requests are JSON, one per connection; response includes success/error with bounded content. Server startup uses the same executable with `--server` and no visible extra console.

- [ ] GREEN: focused daemon tests plus `crewterm doctor` and real CLI smoke; never spawn installed AI agents during tests.
